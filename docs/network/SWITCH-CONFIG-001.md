## 3. Конфигурация коммутатора — bond0 (ens2f0 + ens2f1)

### LAG/bond

```text
Тип: LACP (802.3ad) — предпочтительно
Fallback: режим active-backup на серверах (если LACP невозможен)

Порты каждого сервера должны быть в ОДНОМ LAG.
Если используется MLAG/MC-LAG/VPC/stack между двумя коммутаторами:
  — ОДИН логический LACP peer на сервер
  — port-channel/LAG с两台 коммутаторов
```

## 5. Серверная конфигурация (что настроит Hermes после switch-side)

```text
bond0:
  mode: 802.3ad | active-backup
  slaves: ens2f0 + ens2f1
  VLAN: 700, 140, 143

bond1:
  mode: 802.3ad | active-backup
  slaves: ens2f2 + ens2f3
  VLAN: 141

На всех трёх узлах идентично.
```

## 6. Проверка после настройки коммутаторов

```text
□ LACP установлен для каждого LAG
□ VLAN 140 tagged на портах bond0
□ VLAN 141 tagged на портах bond1
□ VLAN 700 tagged на портах bond0 (сохранён)
□ VLAN 143 зарезервирован на портах bond0
□ Связность между серверами по каждому VLAN подтверждена
□ LLDP/CDP включён для идентификации портов
```

## 8. Что требуется от сетевого инженера

1. Идентифицировать коммутаторы и порты для каждого NIC серверов.
2. Указать модель коммутаторов и поддержку MLAG/MC-LAG (нужно для LACP).
3. Настроить VLAN 140, 141, 143 (tagged) на соответствующих портах.
4. Настроить LACP (802.3ad) port-channel/LAG для bond0 и bond1.
5. Сохранить VLAN 700 на bond0.
6. Подтвердить или опровергнуть возможность LACP (→ выбор active-backup).
7. Для node-03: применить ту же конфигурацию после определения MAC.
8. Сообщить gateway для VLAN 140 (если нужен).
