## Blocking findings and finite closure criteria

### SP-01 — discovery is not a gate, and its output is not validated

main() iterates every READ_CONTRACT entry unconditionally; phase only selects output handling.
A discovery reply with groupVersion=wrong.invalid/v9/resources=[] yields rc0 and all four config calls.
FORBIDDEN and TimeoutExpired also still execute all four config reads (overall rc1).
A successful non-JSON discovery body is persisted verbatim, yields rc0 and retains the synthetic canary; extra JSON members are also persisted.

Fix:
- Implement real per-command prerequisites/state, not comments. Unmatched identity/version/resource/scope/read verb or failed discovery must prevent dependent subprocess calls and emit a safe blocked/not-executed record.
- Use explicit dependency relationships: unrelated discovery success cannot authorize a CNPG/Barman configuration read.
- Validate and project discovery responses (expected kind, groupVersion, resource names/kinds/scopes/read capabilities, typed containers/leaves). No raw stdout fallback.
- Bind config reads to the reviewed API version and supported software identity, rather than unqualified preferred-version lookup.
- No arbitrary resources or read commands generated from discovery. Match only the reviewed finite allowlist.
- Tests must assert zero dependent calls on wrong identity, missing resource, unsupported version, malformed JSON, forbidden, timeout and connection failure, plus a positive matching path.

### SP-02 — policy projection copies arbitrary nested content

project_policy_selector_only returns selector/order/ingress/egress/types directly from spec.
Synthetic canaries survive in each of those five output fields, including nested rule metadata.annotations and unexpected token-shaped fields. The current test only checks top-level spec.env/metadata.annotations and cannot detect this.

Fix:
- Explicit recursive, version-specific typed projections for each supported policy kind, not raw rules or reuse of a Kubernetes NetworkPolicy projector.
- Preserve the supported fields necessary for policy meaning (including relevant action/direction/selector/order/precedence/host effects); never claim effective-policy closure after silently discarding an unsupported semantic field.
- Drop non-semantic arbitrary metadata; for unsupported relevant policy semantics report UNKNOWN/UNSUPPORTED and stop dependent completeness claims.
- No annotation/env/inline-config blobs. Tests must include realistic nonempty rules, canaries nested under every output container, invalid leaf types and legitimate counterexamples.
- Malformed input produces safe PARSE_ERROR + empty projected payload, not raw exception/response text.
