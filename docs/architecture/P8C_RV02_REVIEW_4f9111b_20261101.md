## R1 remainder — validate each page before continuing

Current _list_pages still collects RAW dictionaries, calls them validated and only
main projects the combined list after pagination ends. The previous review explicitly
required page projection before journaling success/issuing continuation.

Reproduced for ALL five list types:
1. page1 contains spec="bad" plus next token; page2 is still requested. Final output
   is PARSE_ERROR/empty, but page1 journal cause=null, validated=1. Unsupported
   semantic field has the same delayed-detection problem.
2. After a valid page, TimeoutExpired/OSError returns last_rc=0 at the aggregate
   record while the failed attempt's journal returncode=null. Thus exit no longer
   describes the terminal attempted request. This regresses previously working behavior.
3. Repeated token appends TWO journal entries for the same page. Two real calls
   produce3 entries, with conflicting success/error cause for page1.
4. validated currently equals cumulative RAW dictionary count. This is not a count
   of successful typed projections and can include invalid objects or discarded suffix.

Required implementation, one coherent pass:
- Give the pagination operation access to the selected pure projector. Decode,
  validate envelope, choose the bounded prefix, then project/strict-serialize that
  page before it becomes accepted state or a continuation may be issued.
- Maintain bounded projected accumulator, not an unvalidated raw accumulator.
  main serializes accepted projections; it must not defer first validation until
  after all requests.
- Exactly ONE journal record per attempted request. Construct/finalize it once
  with its actual request metadata, known process code or null, fixed terminal
  cause and truthful counts. Update that record for repeated token/error; never
  append a second entry representing the same request.
- Define counts explicitly: received is that page's raw item count when known;
  validated counts actual successful typed projections (page or cumulative MUST
  be labelled/documented); emitted count separately if discarded/invalidated output
  differs. Do not label raw dictionary presence "validated".
- Malformed page/item/projector or nonfinite projected value ->PARSE_ERROR,
  complete=false, empty affected record output, fixed cause in the failing journal,
  no later request for that read. Unknown semantic field ->UNSUPPORTED with the
  same stop and no raw fallback. Independent scheduled reads continue.
- Terminal attempt timeout/OSError ->aggregate exit=null, matching terminal journal;
  previous successful returncode0 stays only in its own page entry. Transport failure
  after validated pages remains PARTIAL with the validated prefix retained.
- Keep received process0 on JSON/shape/projector failures. This is distinct from
  "no process returncode received" and must not be conflated.
- Preserve valid201 pages200+1, cap500, max3, encoded token without emitted token,
  RV/repeated-token PARTIAL and fixed context. Discarded overflow suffix remains
  UNKNOWN; no requirement to project or emit an unbounded suffix.
