## FU-03 — truthful errors, exit codes and page journal (blocking)

first_page_forbidden/not_served/connection all return PARTIAL with exit=0,
rather than their distinct causes; first_page_timeout also records exit=0.
Later timeout discards prior valid objects; later failure loses the cause.
Only initial argv is recorded even when a different continuation request ran.
complete can stay true after projector PARSE_ERROR.

Fix:
- before any valid page: classify actual FORBIDDEN/API_NOT_SERVED/CONNECTION/
  TIMEOUT/GET_FAILED; preserve actual process returncode, null if not obtained.
- after valid pages, transport/API failure: PARTIAL, complete=false, retain only
  already validated objects and fixed failure cause/category; no raw stderr.
- malformed list/item/projector result: PARSE_ERROR, empty affected record output,
  complete=false; unknown semantic field UNSUPPORTED, never partial raw output.
- no made-up exit=0; aggregate exit nonzero if any partial/error/blocked row.
- journal every attempted page with page number, requested limit, start/end,
  actual returncode or null, fixed cause and counts.
Continue token must NOT be emitted. Mark any argv continuation value explicitly
redacted rather than claiming the displayed argv is byte-identical; fixed path and
limit remain visible. Test literal actual argv in mocks with synthetic token.
This reconciles evidence traceability with the existing no-token-output rule.

## FU-06 — semantic fields, null versus absent, and exact types (blocking)

explicit null becomes {} (match-all), changing meaning.
protocols_null is accepted; explicit-null selector values and HEP profiles/expectedIPs

Duplicate schema set-list members are accepted. Tier labels are dropped; Tier NaN/Inf

Fix:

  null must be rejected; preserve genuine {} selectors and empty arrays where legal.
- per-direction rule allowlists: ingress permits from but not to; egress to but not
  from. Wrong-direction unknown semantics → UNSUPPORTED, not silent loss.
- validate all nested fields against the finite pinned contract, not broad coercion;
  reject duplicate set-list members (CNP networks, HEP expectedIPs/profiles).
- preserve typed metadata.labels where the plan requires them (including Tier).
- exact schema types/bounds, avoiding unsupported extra constraints. HEP port.name
  is a required string in the chosen schema; either accept its legal empty value
  or propose a separately justified narrower contract rather than claiming schema equality.
- reject nonfinite order and related inherited numeric fields at followup boundary.
Keep accepted S1 identity logic and old projectors unchanged; apply strict wrappers
where this new collector promises stronger checks.
