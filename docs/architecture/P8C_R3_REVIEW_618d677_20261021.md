## RV-03 — transport timeout отменяет body до чтения
portal/internal/collectors/transport.go:
RoundTrip делает context.WithTimeout + defer cancel(), вызывает base.RoundTrip и возвращает resp. Cancel выполняется до чтения response Body вызывающим client-go. При потоковом/задержанном body это прерывает чтение. Статический вывод по lifecycle net/http, не заявляется actual Go reproduction здесь.
Исправить lifetime deadline так, чтобы 5s охватывали весь запрос и чтение body, cancel при error/redirect/Close/EOF; либо использовать поддержанный client timeout. Добавить real httptest TLS server: headers flush, delayed JSON body внутри5s успешно; >5s timeout; отмена родителя; отсутствие leaks. Нынешние fake RoundTripper ответы этот дефект не выявляют.
Также canonical constructor принимает http scheme из apiURL, а path grammar разрешает произвольные namespace/name для approved GVR. Закрыть уже заданные HTTPS и exact named-object restrictions без расширения RBAC.

## RV-06 — persistence/schema closure не доказан
1. initial lag=-1 выдается handleHealth как number. Утверждённый OpenAPI Health.persistenceLagSeconds допускает null либо number minimum0. Это нарушение контракта; использовать null для отсутствия успеха либо иной уже допустимый смысл, не менять контракт под sentinel. Lag рассчитывать по времени ответа/состояния, не замораживать между failures.
2. transitions — только memory diagnostic slice; Transitions() нигде в production не читается, queue не попадает в timeline/DB и не восстанавливается. RecordTransition добавляет ok/failed при каждом цикле без dedup изменения состояния. platform status transitions отсутствуют. DataLoss сбрасывается после последней успешной записи, даже когда пропущенные события не восстановлены. Доделать bounded fallback/flush/recovery и честную loss semantics.
3. TestPersistenceRecovery вручную изменяет atomics и копирует success branch вместо исполнения persistOnce/реального writer failure/recovery. Это не проверка production path. Подключить контролируемый store seam или isolated DB, test actual persistence flow, queue overflow/backpressure/dedup/readback/cleanup failure.
4. VerifySchema не проверяет timeline_events.id/object_kind/object_namespace/object_name, используемые ListEvents/Upsert/Prune, и вообще не проверяет типы/нужные constraints. SELECT col LIMIT0 пропускает несовместимый тип. Дополнить expected schema check и negative tests missing-column/type/unique constraint при intact ledger. Не трогать infrastructure tables.
5. TLS min/SNI присутствуют, но комментарий "no PG* overrides" не доказан одним explicit subset connstr. Проверить и зафиксировать запрет ambient routing/TLS/session overrides и fallback по исходному DB contract.
