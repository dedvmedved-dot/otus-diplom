# P8 Portal DB Interface Contract

Deliverable of P8A-R1. Defines the connectivity contract for the Portal application.
Does NOT define final business schema (that is future P8C).

```text
NAMESPACE:             portal
CNPG_CLUSTER:          portal-db
DATABASE:              portal
APPLICATION_ROLE:      portal_app
WRITE_ENDPOINT:        portal-db-rw.portal.svc:5432
READ_ENDPOINT:         portal-db-ro.portal.svc:5432
GENERAL_ENDPOINT:      portal-db-r.portal.svc:5432
CREDENTIAL_SECRET_REF: portal/portal-db-app
CREDENTIAL_VALUES:     OUT_OF_BAND / NEVER IN GIT
TLS:                   required
TLS_CANONICAL_TARGET:  verify-full
DATABASE_SCHEMA:       portal
APPLICATION_ACCESS:    non-superuser
DIRECT_POD_CONNECTION: FORBIDDEN FOR PORTAL
WRITE_TRAFFIC:         RW service only
READ_TRAFFIC:          RO service where explicitly designed later
```

## Rules

- Portal must not discover primary Pods itself.
- Portal must not pin a PostgreSQL Pod IP.
- Portal relies on CNPG Services (rw/ro/r).
- Portal does not get postgres superuser credentials.
- Portal migrations belong to future P8C.
- P8A defines connectivity contract only, not final business schema.

## Runtime facts (verified P8A-R1)

- CNPG operator 1.30.1 (digest sha256:b0f9805b...), PostgreSQL 17.10 (digest sha256:ba9e4969...).
- 3 instances, 1 per node, required hostname anti-affinity.
- Streaming async replication (CNPG default), 1 primary + 2 replicas.
- StorageClass piraeus-r2, 10Gi PVC per instance, LINSTOR/DRBD backed.
- Application credential auto-generated by CNPG (random, non-empty).
- TLS: CNPG self-signed CA (portal-db), server cert SAN covers portal-db-rw/ro/r.portal.svc(.cluster.local).
- External exposure: NONE (ClusterIP only, no LB/NodePort/Ingress).
