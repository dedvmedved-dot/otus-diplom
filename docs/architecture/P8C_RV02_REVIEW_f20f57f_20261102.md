## LC-01 — explicit null continue silently accepted

_read_podlist uses meta.get('continue') and skips validation when the result is None.
This collapses absent and explicit null. The previously accepted contract rejects explicit null.

Reproduction: valid PodList with metadata.continue=null yields category=null, complete=true,
overall exit0, safe identity output and FIVE dependent reads. Expected: PARSE_ERROR,
complete=false, empty output and ZERO dependent reads. This regression is missed by116 tests.

Fix only the presence distinction:
- absent continue or explicit empty string: permitted;
- present null, bool, number, list, object: PARSE_ERROR, finite COMPLETENESS diagnostic;
- nonempty string: incomplete/PARSE_ERROR as the existing approved contract specifies;
- never emit token values or exception text.
Use an explicit membership check, not truthiness. Add the supplied regression and
table-driven positive/negative controls. Do not loosen other metadata or identity requirements.

The updated _valid_cidr accepts Python-specific notation that the pinned CEL implementation
rejects. _networks also removed maxLength43 although it is still in the actual Calico schema.

Six independently reproduced false acceptances through the real F-CNP main path:
| Fixture | Submitted value | Required reason for rejection |
|---|---|---|
| dotted_netmask | 10.0.0.5/255.255.255.0 | prefix must be numeric bit length |
| dotted_hostmask | 10.0.0.5/0.0.0.255 | prefix must be numeric bit length |
| zone | fe80::1%eth0/64 | zone identifiers prohibited in prefixes |
| mapped_v6 | ::ffff:192.0.2.1/128 | Kubernetes parseCIDR rejects Is4In6 |
| leading_zero_prefix | 10.0.0.5/024 | netip.ParsePrefix rejects leading-zero prefix lengths |

complete=false, empty output. These are synthetic negative fixtures, not observed live objects.

  https://github.com/golang/go/blob/go1.27.3/src/net/netip/netip.go
