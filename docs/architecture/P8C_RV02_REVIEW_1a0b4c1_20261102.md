## Остаток A — RR-02: критерии проверок не соответствуют API и семантике

### A1. CNPG ready field
В §2 указано `.status.instancesReady`. В CloudNativePG v1.30.1 поле называется
`.status.readyInstances` (также используется printer column Ready).
Источник: официальный cloudnative-pg/cloudnative-pg, api/v1/cluster_types.go,
ref v1.30.1, blob 891424dde2287deffcf22b88683f4d8f96376993.

Исправить ожидание: spec.instances=3, status.instances=3, status.readyInstances=3,
Ready=True, с явной обработкой отсутствующего поля/condition. Не заменять фактический
status ожиданием из spec.

### A2. firstRecoverabilityPoint не является WAL-progress check
Текущая строка требует продвижения `Cluster.status.firstRecoverabilityPoint` за 120s.
В том же исходнике CNPG поле deprecated и не заполняется для backup plugins.
Barman Cloud v0.13.0 api/v1/objectstore_types.go, blob
928d52c982b56f11b2eb00f4f88dea4e75916e12, определяет first recoverability point как
самую раннюю точку восстановления. Это не время последнего архивированного WAL.
Перенос проверки на одноимённое поле ObjectStore не исправит семантическую ошибку.
В принятом P8B_POSTGRES_BACKUP_CONTRACT.md archive_timeout=300s; окно120s само по себе
также не обосновывает ожидание нового WAL при естественной нагрузке.

Удалить неверный критерий. Для доступного в закреплённой версии наблюдения явно разделить:
(1) состояние/отсутствие новой ошибки; (2) timestamp/counter успешного естественного
архивирования после начала стадии, если такой источник действительно доступен.
Указать точный объект/поле или существующий metrics source, reset/absence/error handling.
Не изобретать timestamp или считать старый True свежим сетевым успехом.
Если разрешённого наблюдения недостаточно, честно оставить runtime verification dependency
и STOP перед следующей стадией; не разрабатывать новый collector и не запускать probe.
Отсутствие естественного прогресса = INCONCLUSIVE/STOP, не PASS и не доказанный отказ.
Не требовать нового backup/restore/PITR/failover.

### A3. Исполнимость и rollback
Для каждой строки дать конечный request-timeout, интервал/число наблюдений в общем окне,
точный источник времени. Разделить время GET и время наблюдаемого успеха.
Старый lastTransitionTime не должен автоматически делать стабильный Ready негодным;
свежий GET не делает старое событие свежим. observedGeneration проверять только там,
где поле существует, с явно описанным правилом.

«Нет error-condition» без перечня condition/reason и «operator Pod Ready» без selector
не являются точными условиями. EndpointSlice check должен требовать непустой подходящий
набор endpoints и обработать ready absent/null; пустое множество не проходит по правилу
«все ready». Gateway conditions проверять применительно к текущему generation.

В S2a заменить символ пересечения на объединение разрешений selecting Kubernetes policies.
В S3 policies должны предшествовать созданию соответствующих workloads; «вместе» убрать.
В S4 различить создание Gateway/dataplane и допуск внешних клиентов: Programmed+LB IP
уже могут сделать listener достижимым. Указать существующий механизм/порядок удержания
экспозиции либо честно признать момент экспозиции; нельзя обещать неопределённый
«внешний трафик ещё не допущен». На rollback exposure закрывается до снятия необходимых
ограничений по отдельному deployment-gate.
При неопределённости postcheck описать безопасное состояние остановки/отката;
не оставлять взаимоисключающие «rollback при timeout» и «idle только STOP» без различения.

## Остаток C — RR-01/RR-03: точность exposure и read proposals

### C1. Boundary без нового дизайна
TLS termination + hostname/route match не аутентифицируют клиента.
Зафиксировать выбранную доступность listener для клиентов, имеющих сетевой маршрут,
и существующий прикладной Basic Auth для UI/API.
Источник: portal/internal/httpapi/server.go blob c804bf231fc68bb0cfed1b4a0c058a1b938345d4
(Handler включает auth, затем route); portal/internal/auth/auth.go blob
62c7a0586895bfe2a03fd8207daf5641dc664f0c.
Это разделение транспортной защиты, маршрутизации и аутентификации; не запрос нового auth.

Не утверждать обязательный проход VIP443 → NodePort: наличие nodePort в Service не
доказывает этот hop. В MetalLB L2 VIP объявляется узлом, далее действует Kubernetes
Service forwarding к endpoint10443. NodePort/healthCheckNodePort показать отдельно как
выделенные поля/поверхности, без выдуманной цепочки и без предположения backend dataplane.
Primary reference: https://metallb.io/concepts/layer2/
Сохранение source IP указать как ожидаемую семантику Local до Envoy, не уже измеренный факт.

### C2. PR-3/PR-5
Текущие generic kubectl get списков не гарантируют «single GET, no pagination».
Дать точный versioned endpoint/argv, scope/selectors, projection, request timeout,
completeness и пределы. Это документальные proposals, не код/новый run.

PR-3: EndpointSlice discovery.k8s.io/v1 в default, service-name=kubernetes;
адреса/порт/protocol/ready и непустая полнота; сравнить ожидаемые tuples без
утверждения enforcement. Truncated/error/unsupported → STOP.

PR-5: Service v1 в envoy-gateway-system; selector обязан включать оба
gateway.envoyproxy.io/owning-gateway-name=portal-gateway и
gateway.envoyproxy.io/owning-gateway-namespace=portal.
Проверять ожидаемую cardinality/ownership; не принимать первый Service с совпавшим именем
Gateway другого namespace. Включить spec.healthCheckNodePort и выделенные nodePort,
type, externalTrafficPolicy, ports/protocol/targetPort, UID, selector и LB status.
Runtime имена/IP/UID не угадывать. Недостающие поля/неоднозначность → STOP.

### C3. PR-6 / PR-4
PR-6 проецирует только имя/UID/selectors и потому не обнаруживает изменения rules при
сохранённом UID. В списке отсутствует HostEndpoint, а несколько ресурсов не квалифицированы.
Назвать это конечным freshness comparison исходного policy set, не доказательством
EFFECTIVE_POLICY_UNION. Задать точные GVR/scope для K8s NP, Calico NP/GNP/HEP/Tier/Felix,
CNP и источников labels, от которых зависит сравнение. Для семантических изменений
указать существующую безопасную typed projection или fail-closed change discriminator
с явными ограничениями; unknown/truncation/change → STOP, без raw export.
Не разрабатывать универсальный анализатор политик; использовать принятые источники/контракты.
Проверка default Felix не доказывает effective per-node mode — сохранить ограничение.

PR-4: допустим уже выбранный вариант historical/stale + STOP, без нового runtime probe.
Не утверждать, что никакое разрешённое наблюдение невозможно без exec/log.
Если альтернативный probe остаётся лишь идеей, прямо NOT_EXECUTABLE/NOT_AUTHORIZED;
не называть placeholders «timeout/attempts» исполнимым proposal.
Документальное закрытие не требует выполнить PR-3…6 или устранить live UNKNOWN.
