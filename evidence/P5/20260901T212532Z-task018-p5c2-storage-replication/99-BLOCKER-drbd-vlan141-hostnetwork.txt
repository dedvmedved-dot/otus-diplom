## Блокер (PHASE 13/14/16)

DRBD peer connection НЕ устанавливается. Точное доказательство из dmesg (node-01):

  drbd pvc-... node-02: Configured local address not found, retrying every 10 sec, err=-99
  drbd pvc-... node-03: Configured local address not found, retrying every 10 sec, err=-99

err=-99 == EADDRNOTAVAIL: DRBD kernel transport не может bind локальный адрес
172.30.141.101:7000 (VLAN141).

drbdsetup show подтверждает: _this_host ipv4 172.30.141.101:7000, _cstate Connecting.

## Корневая причина

Satellite pods работают в pod network namespace, НЕ hostNetwork:
  - daemonset linstor-satellite.node-XX: hostNetwork = (empty/false)
  - внутри pod: только inet 10.244.190.9/32 (pod CIDR), lo
  - VLAN141 (172.30.141.101/24 на bond1.141) НЕ виден внутри pod

DRBD device доступен (pod privileged + hostPath /dev), но DRBD NETWORK transport
(порт 7000) требует, чтобы pod видел адрес 172.30.141.x — что возможно только
при hostNetwork: true (или hostPort/multus, которых нет).

## Требуемое решение (вне рамок TASK-018 §26)

Включить hostNetwork: true для satellite pods через штатный механизм оператора:
  LinstorSatelliteConfiguration podTemplate.spec.hostNetwork = true

Это:
  - НЕ reinstall/upgrade Piraeus
  - НЕ version/image change
  - НЕ "network configuration changes on Linux hosts" (host-конфиг VLAN141 не меняется)
  - штатная Piraeus конфигурация для DRBD на выделенной сети

Но это мутация pod networking, которая НЕ перечислена в явно авторизованных
изменениях TASK-018 (§26 allowed files). Требуется явное решение Архитектора.
